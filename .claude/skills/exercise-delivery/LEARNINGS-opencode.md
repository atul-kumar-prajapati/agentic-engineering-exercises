Read at the start of every delivery, alongside every other `LEARNINGS-*.md` in this directory — another agent's file is where you get lessons you have not paid for yet. Append a section per exercise; never edit another agent's file, and never edit `SKILL.md` (propose promotions to the user instead). Push this file to `chore/agentic-exercise-delivery-skill` at the end of the session — see `SKILL.md` Phase 8.

**Already promoted into `SKILL.md`** — do not re-derive or re-record these, they are binding rules now: worktree-before-first-commit and the shared-checkout recovery; the unsatisfiability probe; the zsh `=word` redirect trap; verify subagent claims yourself, including clean verdicts; one subject per commit; never manufacture a worse baseline; an unreported check is not evidence; the two standing guardrails; the generate-the-submitted-pack-once rule; naming the artifact your line citations refer to and re-deriving against it; re-deriving every count you write in prose; running the supplied tool against the fixed state as well as the broken one; declaring the evidence file list in the Phase 2 brief and pasting the Phase 5 checklist in the report; stating the withheld set in before/after comparisons; checking whether an already-complete exercise has been revised since its base.

## The harness (highest value)

- **A parallel exercise session may share this repository checkout.** During 8.1 another session switched the main worktree's HEAD to its own branch mid-run; my first two commits landed on the wrong branch. Fix used: `git reset --soft <foreign-tip> && git restore --staged <my files>` (never touching the foreign commits), then `git worktree add <tmpdir> <my-branch>` and do **all** remaining work in that isolated worktree. Next run: create the dedicated worktree *before* the first commit, not after losing one.
- `verifyGitBinding` (8.1's `evidence-verification.mjs`) diffs `--name-only sourceSha` against the **working tree**, not HEAD. A clean tree at final verification is mandatory; untracked-but-ignored output (`node_modules/`, `dist/`, `*.tsbuildinfo`) is fine because the repo `.gitignore` covers them.
- Commit order that satisfies SHA binding everywhere: (1) implementation commit(s) → that tip is `sourceSha` and must contain generator + workflow; (2) generate the pack with `--sha <that tip>`; (3) capture gate output naming the SHA; (4) one evidence-only commit last. Nothing outside `evidence/` may change after `sourceSha`.
- The 8.1 verify chain was fully satisfiable — no 8.2-style dead end. `.nvmrc` exists at root; `action-pins.json` carries full SHAs; `evidence:generate` omits `--sha` in package.json but CI supplies it via `-- --sha` and the verifier invokes the generator directly. Check these three things first next time; they are the cheap unsatisfiability probes.
- Workflow gate specifics that bite: `permissions` is read from the **top level only**; `npm ci` must match `/^npm ci\s*$/m` exactly; `if: always()` needed on verify **and** upload; `retention-days` 1–7; and the strings `pull_request_target`, `continue-on-error`, `secrets.` are forbidden **anywhere** in the file including comments.
- Size floors (900/1200/1500/1000/600/450 chars) were all reachable with genuine substance — substance only, never filler, per user calibration.

## Session craft

- Matched-condition before/after attempts work well as two parallel read-then-write subagents with disjoint worktrees (one on a `-before` branch from the same base, one on the exercise branch). Give the before agent a deliberately plain prompt; give the after agent the repo's own contracts as its extra input — that is the independent variable, and say so in `comparison.md`.
- A "too good" before attempt is not a problem to fix. 8.1's unstructured attempt preserved every failure and digest; the honest comparison was about what a correct document cannot *enforce* (no commit binding, no executable exit status, no validation, no CI upload). Report reality; don't manufacture a worse baseline.
- zsh gotcha that silently skipped a redirect: `echo ====` in a `;` chain aborts the *entire* command line (`=word` expansion). Verify redirected artifacts exist immediately after writing them (`wc -l`).
- Verify every subagent claim yourself. Both 8.1 subagents reported accurate verification results, but I still re-ran the generator cases and `verifyWorkflow` inline before committing — cheap, and it is the difference between reported and proven.
- Commits: one subject per commit (`generator`, `workflow`, `evidence`) — user calibration from 7.3 applied.

## Verification discipline that paid off

- Run the gate loop with `npm run "$s" >/dev/null 2>&1; echo $?` per script, then `git status --porcelain` (must be empty), then the protected-path guardrail: `git checkout upstream/main -- <all 22 protected paths>` → `verify:exercise` again → still exit 0, still clean. Record all of it.
- `npm run verify:exercise` in 8.1 does **not** run the generator against the submitted `evidence/generated/` in place (it uses temp dirs), so a stale `artifacts/` leftover from running the pass fixture into `evidence/generated/` would only surface via the submitted-pack check. Only ever point `evidence:generate` at the failing fixture.

## 9.1 — security/a11y review gauntlet

- **The shipped `semgrep.yml` cannot run — twice over.** It is invalid YAML (unquoted pattern contains `__html: $SOURCE`, i.e. colon+space in a plain scalar) *and* its literal pattern `<... dangerouslySetInnerHTML={{ __html: $SOURCE }} ... />` fails semgrep pattern parsing ("no pattern found") even after quoting. Working equivalent: pattern `"<$EL dangerouslySetInnerHTML={{ __html: $SOURCE }} />"` with the same id/message/severity/languages. Run it against a clone of the bundle head, document the substitution in `evidence/semgrep.txt`, never touch the protected file. Semgrep was also absent from the machine — installed into a throwaway venv under the opencode temp dir, not globally.
- **Findings' `line` values reference the review head inside the bundle, not the working tree.** `review-expectations.json` pins SEC-001→ActionComposer.tsx:31, VAL-001→:48, A11Y-001→WorkQueue.tsx:16 — those are the bundle head's (expanded-formatting) line numbers; the working-tree starter is a condensed reformat with different numbering. Clone the bundle and confirm each pinned line before writing `review.json`; the verifier compares fields exactly.
- **`tests/` is type-checked (tsconfig includes it) but there is no @types/node and package.json is protected** — `node:fs` imports fail typecheck. Use Vite `?raw` imports plus a small `tests/raw-modules.d.ts` ambient `declare module "*?raw"` (the declaration must be a .d.ts; inline in the test file it becomes an invalid augmentation).
- **`verifyGitBinding` here is the 7.1 pattern:** implementation commit (fixes + learner tests) = `sourceSha`; then write evidence; capture `npm run review:verify` while HEAD == sourceSha (untracked evidence files are invisible to `git diff --name-only sourceSha`, so this works); then one evidence-only commit. Nothing outside `evidence/` may change after `sourceSha`.
- **zsh/BSD gotcha that cost a re-run:** `xargs -I{} git checkout upstream/main -- "{}}"` injects a literal `}`; use a `while IFS= read -r p` loop over the protected-path list (the LEARNINGS-cursor fix, still relevant on BSD xargs).
- A one-word test-fixture bug: `"approved"` is exactly 8 chars and is NOT a short note — the protected server test's short fixtures are "approve"/"ok"/"1234567". Match that boundary.
- Baseline worth recording: `agent:check` exits 0 on the vulnerable head — the seeded defects are invisible to quality gates; only `test:review`/`review:verify` catch them.

## 9.2 — fresh-agent diff triage

- **The fresh-session review works exactly as designed.** A general subagent given only the brief, manifest, and diff (plus a mounted read-only copy of the head source for reproduction) independently derived all four blockers with correct head line numbers and correctly dismissed the seeded saveAction-mutation claim when asked directly — no hints leaked. Mounting the head in an isolated sandbox is the cheapest way to let the reviewer "reproduce" without giving it repo history.
- **`sourceSha` has a three-file exact-match constraint here** (verifyGitBinding: `diff-tree --name-only` of the sourceSha commit must equal exactly App.tsx, workflowApi.ts, tests/cache-regressions.test.ts, sorted; everything after sourceSha must be evidence-only). Commit the remediation as one commit touching exactly those three, then all evidence in a second commit.
- **`focused-tests.txt` needs vitest's verbose reporter.** Default reporter collapses passing tests to file-level lines, so the describe name "protected cache acceptance" (a required substring) never appears. `npm run test:cache -- --reporter=verbose` appends the flag to the *last* command in the script (the node script), not vitest — run `npx vitest run <files> --reporter=verbose` and `node ./scripts/run-app-cache-checks.mjs` separately and capture both with exit codes.
- **`fixture-verification.txt` has an 80-non-whitespace-char floor** while the script's own output is ~60 chars — enrich with the genuine `git bundle list-heads` output. The submission contract's minCharacters applies to *non-whitespace* characters.
- **`tests/` imports must be `../src/...`**, not `../...` (vitest resolves from the test file's directory; `../data/workItems` from `tests/` fails to load).
- **saveAction fix shape:** read cache-or-defaults (`readCachedItems() ?? [...workItems]`), build the updated object, `setItem` the merged list — this satisfies the protected "persists an update and reads it on the next load" acceptance test. `collectEvidence` needs no storage access at all; `fetchWorkItems` defaults must be `[...workItems].sort(...)`.
- **Recheck lane found a test gap that is by design:** no component-level filter-change test (would need @testing-library/react; package.json protected). The designed guard for CACHE-001 is the protected `run-app-cache-checks.mjs` (forbids `clearCachedWorkflowItems` in App.tsx). Document the gap honestly in comparison.md instead of forcing unavailable tooling.
- Guardrails ran before the evidence commit this time (calibration #1 addressed); the intermediate verify:exercise failure it surfaced (short fixture-verification.txt) was an evidence-file issue, not a protected-input issue — enriched the file, re-ran, exit 0.

## 11.1 — characterization-first rules refactor

- **The unconstrained before-attempt must be starved of the workflow, not just un instructed.** "You may read any file in the exercise directory" is a leak: the README *and* `src/labContract.ts` both teach the characterization-first workflow, and a capable agent will simply execute the exercise itself (my first before run produced history.json and behavior-decisions.md — a contaminated run). Working isolation: a sparse-checkout worktree of the before branch showing only `rules-refactor-app/src/**` minus `labContract.ts` — `git sparse-checkout set --no-cone '/.gitignore' '/<exercise>/rules-refactor-app/src/**' '!/<exercise>/rules-refactor-app/src/labContract.ts'`. Keep `/.gitignore` in the set or node_modules becomes visible-untracked. Run `git sparse-checkout disable` after the attempt to run gates in that worktree. Disclose every discarded launch in before.md ("Retries: 0" describes the recorded run; the discarded ones are session notes).
- **A task call can return `completed` with an empty result and zero work done.** Before treating a subagent return as an attempt, check `git log`/`git status` in its worktree; a hollow invocation is an infrastructure failure to disclose and relaunch, not an agent attempt to review.
- **Never capture `npm run verify:exercise` output into the repo while it runs.** `run-clean-verification.mjs` snapshots untracked files before/after its inner `verify:exercise:core`; a capture file inside the repo grows between those snapshots and fails the guard as "untracked file changed". Redirect to /tmp, then copy into `evidence/commands/` after the run.
- **Characterization test path depth:** from `src/rules/` the golden cases are three levels up (`../../../docs/renewal-golden-cases.json`), not two as from `scripts/` — first run ENOENTs.
- **History contract (verify-refactor-submission.mjs):** characterizationSha's diff-tree must equal exactly `[<exercise>/evidence/before-output.json, <exercise>/rules-refactor-app/src/rules/legacyEligibility.characterization.test.mjs]` (sorted string compare); refactorSha's exactly one file; commits after refactorSha evidence-only; nothing binds after.md's Implementation commit to refactorSha — they are independent contracts, and after.md's implementation commit can be the agent's unaided attempt while history.json records the single-file refactor commit.
- **Patches must be generated in the main worktree** with the exact contract command (`git diff --binary --full-index <start> <impl>`) so they are byte-identical to what `comparable-evidence.mjs` recomputes in the same repo/config.
- **The sharpest finding came from the lanes, not the gates:** both first-match-wins table refactors re-read `tier` (3×) and `monthsActive` (2×) where the original's else-if cascade reads each property once per branch — outputs diverge for stateful-accessor inputs (per-read-varying getters, read-once Proxies) while every plain-data input and all ten golden observations stay identical. No gate covers it; a post-hoc module fix would contaminate first-attempt conditions, so it is documented + deferred (integration.md). For any refactor exercise: run a parity lane that hunts property-access semantics, and reproduce lane claims with your own reproducer before accepting them — my 49,392-variation plain-data sweep was blind to exactly this class.
- **before.md/after.md field parsing (comparable-evidence.mjs):** any `Word words: value` line becomes a field; the four match fields (Starting commit, Agent and model, Tools and permissions, Time limit) must be byte-identical strings across both files; describe the environment difference (contracts withheld vs available) in prose, never inside "Tools and permissions". Keep scope labels explicit on "Changed files"/"Lines added and removed" — the patch (cumulative from start) and the implementation commit (single-file) differ for the after run.
- **macOS `/tmp` → `/private/tmp` recurred** in protected-path extraction (`path.relative` produced `../../private/tmp/...` garbage) — take the repo root from `git rev-parse --show-toplevel` (the 10.3 cursor lesson, still biting).
- Branch tip on main now routes gates through root scripts (`run-vite-build.mjs` temp-dir build, `run-clean-verification.mjs` state guard) — the feature branch's older 11.1 package.json differs; base on main. This run: opencode-go/glm-5.3 for me, both first-attempt agents, and all three review lanes (the task tool exposes no per-subagent model selection; the inherited slug is the only one this harness runs).
