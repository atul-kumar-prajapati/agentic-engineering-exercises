# Skill Benchmark and Package Gate Evidence

Record observed runs. Do not infer token counts, timings, or assertion results.

## Workspace layout

Create every path below for evals 1 to 4, configurations `without_skill`, `starter_skill`, and `with_skill`, and runs 1 to 3:

```text
benchmark-workspace/
  eval-1/
    without_skill/
      run-1/
        outputs/incident-summary.md
        timing.json
        grading.json
    starter_skill/
    with_skill/
```

Use `npm run eval:grade -- <eval-id> <output-path> <grading-path>` to create each `grading.json`. Do not edit generated grades.

## timing.json

```json
{
  "eval_id": 1,
  "configuration": "without_skill",
  "run_number": 1,
  "agent": "agent name and version",
  "model": "model name and version",
  "runtime": "client or runtime version",
  "tools": ["enabled tool names"],
  "permissions": "permission mode",
  "repository_commit": "40-character starting commit",
  "time_limit_minutes": 10,
  "attempt": 1,
  "skill_tree_sha256": null,
  "total_tokens": 1000,
  "duration_ms": 30000,
  "total_duration_seconds": 30
}
```

Use `null` for the no-skill hash. Use the hash printed by `npm run eval:fixtures` for `starter_skill` and the hash printed by `npm run skill:validate` for `with_skill`.

## skill-record.md

- Skill-creator source URL and 40-character source commit.
- Installed `SKILL.md` path and SHA-256.
- Installation command or method.
- Agent, model, tools, permissions, time limit, and repository commit used for all runs.

## analysis.md

Identify training failures that motivated the skill changes. Compare held-out quality, critical failures, variance, tokens, and elapsed time across all three lanes. Note outliers or non-discriminating assertions and state the package adoption decision.

## decision.json

After running `npm run benchmark:aggregate`, copy the printed benchmark SHA-256 and create:

```json
{
  "schema_version": 1,
  "decision": "package",
  "benchmark_sha256": "SHA-256 of evidence/benchmark.json",
  "reason": "Measured reason tied to the applicable gate checks"
}
```

Use `package` only when the generated gate passes. Use `reject` only when all common checks pass but the comparison mode proves no added value. If a common check fails, revise and rerun instead of submitting. A rejection must leave both `dist/incident-summary.skill` and `evidence/package-manifest.json` absent.

`benchmark.json` and `benchmark.md` are generated by the supplied commands. `package-manifest.json` is generated only for a passing candidate. Do not edit generated files.

## Required Run Files

- `evidence/before.md` records the no-skill and unchanged-starter conditions, run counts, quality, failures, tokens, duration, and skill hash.
- `evidence/before.patch` contains the unchanged starter skill snapshot and baseline evidence as a genuine Git diff.
- `evidence/after.md` records the matching improved-skill conditions and generated metrics.
- `evidence/after.patch` contains the evaluated skill change as a genuine Git diff.
- `evidence/comparison.md` compares all three lanes and states whether packaging is allowed.
