# Exercise 02 : Superpowers Skill-Driven Development

## Your Mission

Your mission is to use a skill-driven coding workflow to design and safely implement a team invitation feature.

You are given a working application with team roles and workspace policies, but no invitation lifecycle. An agent that starts coding immediately may allow unauthorized invitations, create duplicates, ignore workspace policy, or accept expired invitations.

Use Superpowers to move from the feature request through design, planning, test-driven implementation, review, and final verification.

You must also prove how the workflow affected the agent's work by comparing its behaviour before and after Superpowers was enabled.

The duration for this challenge is 60 min or less.

## Project

[team-collaboration-app](./team-collaboration-app) contains the application code for this exercise.

Use the following feature request for both agent runs:

> Add a Team Invitations section. An active owner or admin allowed by the workspace policy may invite an email as a member or guest. Guest invitations are allowed only when the workspace policy permits them. Prevent invitations for existing members or an email with a pending invitation. Invitations must use the configured expiry period and may be accepted or revoked only once. Rejected actions must not change invitation or member data.

## How To Go About It

Choose a coding agent supported by [Superpowers](https://github.com/obra/superpowers). Use the installation method documented for that agent.

First, start a fresh agent session without Superpowers and give it the feature request. Record how it investigated, planned, tested, and implemented the feature. Save the implementation as evidence, then revert it.

Enable Superpowers and start another fresh session with the same feature request.

Follow the skills selected by Superpowers. The workflow must include:

- Brainstorming and approval of the feature design before implementation.
- An implementation plan connected to the approved design.
- Test-driven development with a recorded failing test before production code.
- Implementation using the execution workflow selected by Superpowers.
- Code review and verification before completion.

Keep the design and plan in the locations generated by your installed Superpowers version.

Use the same agent, model, tools, permissions, and time limit for both runs. Do not rerun a session to obtain a preferred result.

## Evidence

Submit:

- The completed invitation implementation and automated tests.
- The design and implementation plan produced through Superpowers.
- `evidence/before.md` describing the agent's behaviour without Superpowers.
- `evidence/before.patch` containing the first implementation.
- `evidence/after.md` describing the Superpowers-driven implementation.
- `evidence/after.patch` containing the final implementation.
- `evidence/comparison.md` explaining what changed between the two runs.
- `evidence/skill-usage.md` listing the Superpowers skills used and their generated artifacts.
- `evidence/tdd.md` containing the failing test result followed by the passing result.
- `evidence/review.md` containing the code-review findings and their resolution.
- Output from `npm run test:invitations`, `npm run submission:verify`, and `npm run agent:check`.
- A focused pull request containing only the exercise changes.

Use the supplied [invitation contract](./docs/invitation-contract.md), [evidence template](./docs/evidence-template.md), and repository [submission standard](../../docs/SUBMISSION_STANDARD.md).

## Evaluation

Reviewers will check that both runs used the same conditions, the Superpowers workflow was actually followed, the design was approved before planning and coding, and test failure was recorded before implementation.

The final feature must enforce invitation permissions, workspace guest policy, case-insensitive duplicate prevention, configured expiry, single-use acceptance and revocation, and no state mutation when an action is rejected.

The exercise is incomplete if the workflow artifacts were written after the implementation, the evidence is self-declared, invitation edge cases are missing, or the required checks do not pass.

See the [Superpowers Skill-Driven Development evaluation rubric](../../docs/EVALUATION_RUBRICS.md#superpowers-skill-driven-development).
