# Exercise 02 : Superpowers Skill-Driven Development

## Your Mission

Your mission is to use a skill-driven workflow to design and implement a team invitation feature.

The application contains team roles and workspace policies but has no invitation lifecycle. The implementation must handle authorization, duplicates, guest policy, expiry, acceptance, and revocation.

Use Superpowers to complete the design, planning, test-driven implementation, code review, and verification.

Compare the agent's implementation before and after enabling Superpowers.

The duration for this challenge is 60 min or less.

## Project

[team-collaboration-app](./team-collaboration-app) contains the application code and invitation rules.

Use this request for both agent runs:

> Add a Team Invitations section. An active owner or admin allowed by the workspace policy may invite an email as a member or guest. Guest invitations are allowed only when the workspace policy permits them. Prevent invitations for existing members or an email with a pending invitation. Invitations must use the configured expiry period and may be accepted or revoked only once. Rejected actions must not change invitation or member data.

## How To Go About It

Install [Superpowers](https://github.com/obra/superpowers) using the instructions for your coding agent.

Start a fresh agent session without Superpowers. Provide the feature request, save the first implementation and observations, then revert the implementation.

Enable Superpowers and start another fresh session with the same request. Follow its workflow in this order:

- Approve the feature design before implementation.
- Create an implementation plan from the approved design.
- Write and run a failing test before changing production code.
- Implement the feature using the selected execution workflow.
- Complete code review and final verification.

Keep the design and plan in the locations generated by Superpowers.

Use the same agent, model, tools, permissions, prompt, time limit, and first attempt for both runs. Do not rerun either implementation.

## Evidence

Submit:

- The completed invitation feature and automated tests.
- The Superpowers design and implementation plan.
- `evidence/before.md` and `evidence/before.patch`.
- `evidence/after.md` and `evidence/after.patch`.
- `evidence/comparison.md` explaining what improved.
- `evidence/skill-usage.md` listing the skills used and generated artifacts.
- `evidence/tdd.md` showing the failing test followed by the passing result.
- `evidence/review.md` containing review findings and their resolution.
- Output from `npm run test:invitations`, `npm run submission:verify`, and `npm run agent:check`.
- A focused pull request containing only the exercise changes.

Use the [invitation contract](./docs/invitation-contract.md), [evidence template](./docs/evidence-template.md), and repository [submission standard](../../docs/SUBMISSION_STANDARD.md).

## Evaluation

The evidence must prove that design approval, planning, failing tests, implementation, review, and verification occurred in the required order.

The final feature must enforce invitation permissions, guest policy, case-insensitive duplicate prevention, configured expiry, and single-use acceptance and revocation. Rejected actions must not change invitation or member data.

The exercise is incomplete if the runs are not comparable, workflow artifacts were created after implementation, evidence is unsupported, protected inputs are changed, or the required checks fail.

See the [evaluation rubric](../../docs/EVALUATION_RUBRICS.md#superpowers-skill-driven-development).
